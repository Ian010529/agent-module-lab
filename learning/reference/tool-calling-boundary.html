Reference tool loop

@tool
  ↓
get_tools(...)
  ↓
llm.bind_tools(...)
  ↓
LLM returns AIMessage.tool_calls
  ↓
{name, args, id}
  ↓
tools_by_name[name]
  ↓
tool.invoke(args)
  ↓
role="tool", tool_call_id=id
  ↓
LLM sees observation

每层是谁负责

层责任
Application定义能力、选择暴露的 Tools、执行 Tool、做权限/HITL、控制 deterministic workflow。
LLM在已暴露 action surface 中，根据语义产生 tool call 的 name / args。
Tool result由 application 执行后形成 observation，再作为 tool message 回到模型。

Tool vs direct call

问题倾向
模型需要根据语义在多个动作中选择吗？Controlled Agent Tool
Workflow 已经知道下一步必须调用哪个接口吗？Direct function / API call
函数访问外部 API/DB 吗？这本身不能决定是否是 Agent Tool
已知事实满足明确阈值/集合规则吗？Deterministic code
