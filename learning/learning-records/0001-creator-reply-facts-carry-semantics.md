# Creator reply facts carry semantics

The user demonstrated that a number alone is not a sufficient representation of a creator quote: “usual fee” is different from a final quote, missing currency must remain unknown rather than inferred, paid-usage conditions can change the price, and budget comparison belongs in deterministic code. They also identified that a single `price_amount` loses the relationship between multiple prices and their conditions, so future teaching can start from semantic-preserving schema design rather than re-teaching this distinction.

## Evidence

In creator-reply examples, the user correctly distinguished a usual rate from a project quote, identified explicit currency absence, recognized conditional pricing, routed budget comparison to code, and rejected a single-price schema when two conditional prices were present.
