# AI 提效模块项目计划

## 1. 项目目标

通过开源项目的理解与二次开发，具备**独立负责一个 AI 提效模块**的能力，包括需求定义、架构设计、技术选型、开发集成、评测和问题排查。

使用 vibe coding 提高实现效率，但不能把设计和判断全部交给 AI。需要掌控：

- **业务与模块边界：**解决什么问题，输入输出是什么，依赖哪些外部数据或接口。
- **架构与技术取舍：**为什么采用当前设计，为什么选择某个组件，是否存在更简单的替代方案。
- **运行与效果：**系统如何执行，失败时如何处理，怎样验证正确性、可靠性和提效效果。

不以从零手写全部代码、使用框架数量或做出完整平台为目标。

## 2. 第一主项目：Creator Outreach / Reply Copilot

### 参考仓库

`langchain-ai/agents-from-scratch`

### 要做什么

将邮件助手改造成一个**达人外联与回复处理模块**，利用已有活动资料、达人资料和邮件线程，辅助处理合作沟通。

主要功能：

| 功能 | 具体范围 |
|---|---|
| 回复理解 | 识别合作兴趣、报价、寄样询问、拒绝和需要人工判断等情况 |
| 信息提取 | 提取报价、币种、交付要求、时间等关键事实，保留缺失和不确定信息 |
| 上下文获取 | 根据需要调用接口，获取活动要求、合作条件和历史沟通 |
| 建议与草稿 | 生成有资料依据的下一步建议和回复草稿，不编造业务事实或承诺 |
| 人工介入 | 对超出权限、涉及业务承诺或无法可靠判断的情况请求人工处理 |
| 状态与异常处理 | 记录处理状态，处理重复输入、工具失败、超时及恢复执行 |

默认只生成建议或草稿，**不自动接受报价、承诺寄样、修改预算或发送真实商务邮件**。

### 要掌控的设计

明确固定工作流与 Agent 动态决策各自负责什么；理解上下文构建、工具调用、状态管理、权限检查、人工审批和停止条件。

对于信息缺失的任务，能够设计“补查资料、请求澄清或转人工”的处理方式，而不是只做一次模型调用后直接返回文本。

## 3. 后续可选项目：Creator / Competitor Research Copilot

### 参考仓库

`assafelovic/gpt-researcher`

### 要做什么

开发一个**达人或竞品研究模块**。根据研究目标和提供的资料，获取相关信息，形成有证据支持的分析结果。

范围包括研究任务拆分、检索与资料筛选、证据整理，以及结构化输出。结果应区分事实、分析判断和未知信息，保留来源。

### 要掌控的设计

理解何时直接查询 API 或数据库，何时使用搜索或 RAG；判断是否需要动态规划、并行任务或多 Agent，以及如何限制研究范围、执行步数和成本。

不开发完整研究平台，也不把大规模数据采集作为前置任务。

## 4. 后续可选项目：Campaign Performance Analyst

### 参考仓库

`vanna-ai/vanna`

### 要做什么

开发一个**活动表现分析模块**。基于已有结构化数据，回答指标查询、表现对比和异常分析问题，并提供可核对的数据依据。

范围包括指标定义、受控查询、结果校验和分析说明。对于数据无法支持的原因，不把猜测写成确定结论。

### 要掌控的设计

理解业务指标与数据表的对应关系，判断采用固定查询工具还是自然语言生成 SQL，并设计数据访问权限、查询限制和结果验证。

不重做完整 BI 系统、数据仓库或 Dashboard。

## 5. 评测：贯穿实际开展的项目

### 参考仓库

`sierra-research/tau2-bench`

### 要做什么

为实际开发的模块建立可复现的测试与评测，借鉴“政策、工具、任务、环境”的组织方式。

**评测不是独立替代业务开发的主项目，也不默认要求新增 benchmark 或自定义领域。**

评测覆盖：

| 维度 | 检查内容 |
|---|---|
| 任务正确性 | 信息提取、工具选择、工具参数和最终状态是否正确 |
| 输出质量 | 内容是否有依据，是否遗漏关键信息或编造承诺 |
| 权限与风险 | 是否越权，是否正确触发人工介入，是否泄露不应访问的数据 |
| 运行可靠性 | 重复请求、接口超时、模型失败和恢复执行是否得到正确处理 |
| 提效效果 | 与简单基线或人工流程比较完成质量、人工修改量、成本和延迟 |

能够用程序明确判断的事项优先使用确定性检查；LLM judge 只用于适合它的辅助质量评估。

## 6. 数据与开发边界

练习可使用开源项目自带数据、固定测试数据和模拟接口。开发案例与保留验收案例分开。

模拟数据用于验证功能和工程行为，不能据此宣称真实业务转化率或收益提升。不使用或上传未经授权的真实邮件、个人资料、内部数据和代码。

**只开发边界明确的模块，不搭建完整平台。**不重做 CRM、达人库、Campaign 管理系统、邮箱客户端、通用权限系统或管理后台。模拟接口只服务于模块运行和测试，不扩展成另一套业务底座。

不预先规定必须使用 RAG、Memory、Multi-Agent、MCP、Redis 或消息队列；是否引入，取决于实际需求和替代方案比较。

## 7. 项目范围与交付

**当前拟定主线：**Creator Outreach / Reply Copilot，包含必要的数据、测试和评测。

**后续可选：**研究模块、活动分析模块，不同时展开，不默认列入第一阶段交付。

每个实际开展的项目保留以下交付：可运行的模块、简短的架构与技术取舍说明、可复现的测试与评测，以及必要的运行和故障处理说明。

完成标准是：**能够解释设计、调整需求、审查 AI 生成的关键代码、定位失败，并用测试验证修改，而不只是运行一个 Demo。**
